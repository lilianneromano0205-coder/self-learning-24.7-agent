# Literature Research Pass: Personal Cognitive Clone System
Research for AI lab building a system that observes one person's decisions/approvals/rejections/messages, builds a structured self-model, predicts choices with probabilities, scores in shadow mode, and detects policy drift.

Status: COMPLETE.

## 1. Experience capture datasets/traces of human computer use

**1.1 Mind2Web (Deng et al., NeurIPS 2023 Spotlight)**
URL: https://arxiv.org/abs/2306.06070 ; https://osu-nlp-group.github.io/Mind2Web/ ; https://github.com/OSU-NLP-Group/Mind2Web
First dataset for generalist web agents: 2,000+ open-ended tasks crowdsourced across 137 real websites / 31 domains, with full human action traces (train split: 1,009 tasks / 73 sites / 7,775 samples). Each step is a (Target Element, Operation) pair — Click/Hover/Enter, Type, or Select Option — captured via a Playwright-based recorder that snapshots the live DOM at each step, alongside raw HTML, screenshots, and network traffic. This is the closest published analog to "structured event capture of one person's UI decisions": every action is timestamped, grounded to a specific element, and typed by operation, which is exactly the schema a personal clone needs (element target + operation type + surrounding DOM state).
IMPLEMENTATION HOOK: Mirror the (Target Element, Operation) tuple as the atomic JSON ledger record — `{ts, app, element_id/selector, operation: click|type|select, value?, dom_or_context_hash}` — one JSON line per action, append-only file per session; this gives you a stdlib-only (json + hashlib) capture format compatible with a published schema for later benchmarking.

**1.2 OSWorld (Xie et al., NeurIPS 2024 Datasets & Benchmarks)**
URL: https://arxiv.org/abs/2404.07972 (paper); https://os-world.github.io/
369 real-world tasks spanning Ubuntu/Windows/macOS and 9 applications (email, spreadsheets, file I/O, multi-app workflows via GUI and CLI), with 302 distinct initial VM states and 134 execution-based evaluation scripts (not just final-answer matching — actual side effects in the OS are checked). Human testers solve ~72.4% of tasks vs ~12.2% for the best contemporary agent, establishing a large human-vs-agent gap baseline. Key methodological point: evaluation is execution-based (checking resulting file/state changes), not trajectory-matching — directly relevant to "was the predicted action actually correct," not just "did it look similar."
IMPLEMENTATION HOOK: Adopt execution-based (state-diff) grading over trajectory-similarity grading when scoring the clone in shadow mode — store a pre/post state hash or diff per decision in the ledger and grade predictions by whether they reproduce the actual state transition, not string similarity of the predicted action.

**1.3 AgentTrek (ICLR 2025)**
URL: https://arxiv.org/abs/2412.09605 ; https://agenttrek.github.io/
Automated pipeline turning web tutorials into agent trajectories at scale, addressing the cost of human-annotated trajectory data: filtered 23,430 web tutorials down to 10,398 successful trajectories across 127 sites, at $0.551/trajectory, using a VLM agent that replays tutorial steps in a live browser and logs observations+actions+reasoning. Trained agents on this synthetic data outperformed those trained on prior human-annotated datasets on multiple web benchmarks. Relevant less for the trace format and more as evidence that reasoning traces (why the action was taken, not just what) meaningfully improve downstream prediction quality — a signal for what fields the personal-clone ledger should capture beyond raw clicks.
IMPLEMENTATION HOOK: Log a free-text "reasoning"/"justification" field alongside every captured decision (even a one-line self-reported rationale or auto-generated context summary) — cheap to add to a JSON ledger record now, high value later for training a rationale-conditioned predictor.

**High-signal event types across these corpora (synthesized, not from one single source):** across GUI-agent literature the consistently high-information events are (a) terminal accept/reject/submit actions (task boundary + outcome label), (b) edits made to an AI-proposed draft/action before acceptance (the diff is a direct preference signal, richer than binary accept/reject), (c) time-to-decision / dwell time before an action (long dwell = high deliberation = high-value training example; near-zero dwell = likely low-signal/habitual), and (d) abandonment/backtrack events (undo, navigate-back) which mark false starts. UNVERIFIED: no single paper in this set quantifies "time-to-decision" as a labeled feature — this is inferred from the general active-learning/uncertainty-sampling literature rather than confirmed in Mind2Web/OSWorld/AgentTrek papers themselves.
IMPLEMENTATION HOOK: Ledger schema should tag every record with `event_type: accept|reject|edit|abandon|backtrack` plus `latency_ms` from first-shown to decision — these two fields alone let a stdlib system (no ML) prioritize which historical records to replay first when building/updating the self-model (edits and long-latency decisions get oversampled).

## 2. Imitation learning

**2.1 DAgger — Dataset Aggregation (Ross, Gordon & Bagnell, AISTATS 2011)**
URL: https://arxiv.org/abs/1011.0686 ("A Reduction of Imitation Learning and Structured Prediction to No-Regret Online Learning")
Shows that naive behavior cloning suffers compounding error under covariate shift: because the learner's own past predictions determine the states it visits next, a small per-step error rate ε can compound to O(T²ε) total error over a horizon T, since mistakes push the policy into states absent from the training distribution where it has never been taught to recover. DAgger fixes this by iterating: roll out the current policy, query the expert (the human) for the correct action at the states actually visited, aggregate this into the training set, and retrain — reducing regret to the no-regret-online-learning bound of O(Tε). Directly explains why a personal clone trained only on the human's historical decisions (pure offline behavior cloning) will degrade exactly on the states its own predictions create, and motivates why shadow-mode scoring against real subsequent choices (not just retrospective fit) is the honest test.
IMPLEMENTATION HOOK: Implement a lightweight DAgger-style loop with stdlib only — log every shadow-mode prediction plus the human's actual later action as a new ledger record tagged `source: dagger_correction`; periodically re-derive decision rules/weights from the aggregated (original + correction) ledger rather than only the original historical log, so the self-model keeps being corrected at the states it actually predicts into, not just the states the human happened to visit unprompted.

**2.2 Agent Workflow Memory / AWM (Wang, Mao, Fried & Neubig, 2024)**
URL: https://arxiv.org/abs/2409.07429 ; https://github.com/zorazrw/agent-workflow-memory
Induces reusable, named "workflows" (e.g., `find_place` → `get_place_zipcode`) from an agent's own past successful trajectories, then stores and selectively retrieves them as additional callable actions/context for future tasks. Improves success rate by 24.6% (Mind2Web) and 51.1% (WebArena) relative to a baseline with no workflow memory, and reduces step count to solve tasks; the online variant (workflows induced continuously during operation, not just offline) generalizes better as the train/test distribution gap widens (+8.9 to +14.0 absolute points over baselines). This is essentially "routine mining" from the person's own trace — a template for extracting the person's habitual multi-step patterns (e.g., "when rejecting invoice X, always also flag vendor Y") into named, reusable rules.
IMPLEMENTATION HOOK: Periodically scan the JSON ledger for repeated action n-grams (same sequence of `event_type`+`object_type` fields within a short time window, appearing ≥ K times) using pure stdlib (collections.Counter over sliding windows of the ledger); promote frequent n-grams to a named "routine" entry in a separate `routines.json` file that the predictor consults before falling back to per-decision statistics — mirrors AWM's induce-then-retrieve pattern without any ML dependency.

**2.3 Routine/task-model induction from computer-use traces (2025-2026 follow-on work)**
URL: "Inducing Task Models from Computer-Use Traces" — https://arxiv.org/abs/2608.20319 ; "WISE-Flow: Workflow-Induced Structured Experience for Self-Evolving Conversational Service Agents" — https://arxiv.org/abs/2601.08158
Task Model Induction (TMI) discovers latent, possibly-interleaved tasks within a single unconstrained trace of computer use (disentangling concurrent activity, e.g., a user switching between two ongoing tasks) rather than assuming one trace = one clean task. WISE-Flow performs offline induction from messy execution logs by contrasting three trace classes — clean successes, error-recovered successes, and failures — to distill reusable procedures, explicitly using the failure/recovery contrast as a signal (not just successes) for what the routine should encode. UNVERIFIED: exact quantitative improvement numbers for TMI and WISE-Flow were not confirmed via direct paper fetch (WebSearch snippet only); treat effect sizes as unconfirmed pending a primary-source read.
IMPLEMENTATION HOOK: When mining routines from the ledger (see 2.2), keep three labeled buckets — `clean_success`, `edited_or_corrected`, `rejected_or_abandoned` — and mine routines separately from each; a routine that recurs in `clean_success` is a candidate autopilot rule, one that recurs in `edited_or_corrected` is a candidate "always modify this way" rule, and one that recurs in `rejected_or_abandoned` is a hard constraint (never propose this).

## 3. Human behavior prediction with LLMs

**3.1 Generative Agents (Park, O'Brien, Cai, Morris, Liang & Bernstein, UIST 2023)**
URL: https://arxiv.org/abs/2304.03442 ; https://github.com/joonspk-research/generative_agents
Introduces an agent architecture — memory stream (raw observations, timestamped) + retrieval (recency/importance/relevance-weighted) + reflection (periodic LLM-generated higher-level inferences over recent memories) + planning (recursive decomposition of daily plans into hourly then fine-grained actions) — that produces believable long-horizon simulated behavior for 25 agents in a sandbox town. The core mechanism (raw log → weighted retrieval → periodic reflective synthesis → plan) is the direct ancestor of "structured self-model built from an observed decision log," and the paper's own ablations show removing reflection or full memory materially hurts believability, i.e., raw logs alone are insufficient — synthesis matters.
IMPLEMENTATION HOOK: Implement the three retrieval weights (recency = exponential decay per elapsed time, importance = a stored scalar per record, relevance = keyword/embedding-free overlap score e.g. Jaccard on tokens) as a pure-Python scoring function over the JSON ledger, and run a scheduled "reflection" pass (stdlib cron-like trigger) that asks the LLM to synthesize N highest-scored recent records into a small number of higher-level self-model statements appended to a `reflections.json` file — this is a direct, buildable port of Park et al.'s architecture onto a JSON-ledger substrate.

**3.2 Generative Agent Simulations of 1,000 People (Park et al., Stanford, arXiv 2411.10109, Nov 2024)**
URL: https://arxiv.org/abs/2411.10109
Builds one generative agent per real person (1,052 participants) grounded in a ~2-hour qualitative life-history interview transcript (not demographics), then evaluates each agent by replaying General Social Survey items and Big Five/economic-game replications and comparing agent answers to the real person's answers. Headline number: agents reproduce their source person's GSS answers with 85% normalized accuracy relative to the person's own two-week test-retest reliability (i.e., 85% of the way to the ceiling set by human self-consistency) — meaning the achievable upper bound for a clone is the person's own noise floor, not 100%. Also shows demographic-only personas have larger accuracy biases by race/ideology than interview-grounded personas, i.e., rich qualitative grounding beats categorical attributes.
IMPLEMENTATION HOOK: When scoring the clone in shadow mode, compute and report accuracy normalized against the human's own test-retest consistency (repeat the same decision/question to the person weeks apart if feasible, or use near-duplicate historical decisions as a proxy) rather than against a naive 100% ceiling — store this as a `human_self_consistency_estimate` field per decision-type in the JSON ledger so downstream metrics (Brier, accuracy) can be reported as "% of human ceiling achieved," directly following this paper's evaluation design.

**3.3 Centaur (Binz et al., Nature 2025, incl. arXiv 2410.20268) — Psych-101 dataset**
URL: https://www.nature.com/articles/s41586-025-09215-4 ; https://arxiv.org/abs/2410.20268
Fine-tunes Llama on Psych-101, a dataset of >10,000,000 individual choices from >60,000 participants across 160 published psychology experiments (each trial expressed in natural language). Result: Centaur predicts held-out participants' trial-by-trial choices better than existing bespoke cognitive models (e.g., reinforcement-learning or Bayesian decision models built for each task individually) and generalizes to unseen cover stories and structurally modified tasks — and its internal representations become more neurally-aligned with human fMRI data despite no explicit training signal for that. Key general lesson: a single model trained on large-scale trial-by-trial natural-language-described choice data outperforms task-specific hand-built models, and does so out-of-distribution — evidence that large heterogeneous behavioral logs beat narrow ones for building a predictive self-model.
IMPLEMENTATION HOOK: Store every decision in the JSON ledger as a natural-language-describable trial (`context_text`, `options_considered`, `choice_made`) rather than only structured fields — this "trial in natural language" format is what let Centaur transfer across task types, and it lets a stdlib system later hand the same records to an LLM for few-shot in-context prediction without a separate feature-engineering step per decision type.

**3.4 Twin-2K-500 (Toubia, Gui, Peng, Merlau, Li & Chen, Marketing Science 2025, arXiv 2505.17479)**
URL: https://arxiv.org/abs/2505.17479 ; https://huggingface.co/datasets/LLM-Digital-Twin/Twin-2K-500
Dataset of 2,058 US participants answering 500+ questions across four survey waves (demographics, psychology, economics, personality, cognitive measures, behavioral-economics experiment replications, a pricing survey), averaging 2.42 hours per participant. Critically, wave 4 repeats earlier tasks to give a genuine test-retest reliability baseline per person — the same "ceiling" concept as 3.2, but released as reusable public data/benchmark rather than embedded in one paper's results, intended explicitly for building and scoring LLM-based digital twins.
IMPLEMENTATION HOOK: Adopt the "repeat a subset of earlier decisions later and compare" design as a periodic self-check task in your own system — inject a small fraction of previously-seen (but not recently-seen) decision contexts back into the shadow-mode evaluation queue on a schedule, purely via ledger bookkeeping (a `repeat_of: <original_record_id>` field), to measure both clone accuracy and the person's own drift/inconsistency with no ML dependency.

## 4. Evaluating a clone

**4.1 RealPref (Guo, Li, Liu & Hooi, arXiv 2603.04191, 2026)**
URL: https://arxiv.org/abs/2603.04191 ; code: github.com/GG14127/RealPref
Benchmark for long-horizon preference-following in personalized user-LLM interaction: 100 user profiles, 1,300 personalized preferences spanning four expression types from fully explicit to fully implicit, tested with multiple-choice/true-false/open-ended questions plus rubric-based LLM-as-judge scoring, over long interaction histories. Central finding: performance drops sharply both as context length grows and as preference expression becomes more implicit, and generalizing preference understanding to genuinely unseen scenarios is the hardest failure mode — directly relevant since a personal clone must infer unstated (implicit) policy from a history of decisions, not just apply preferences the person stated outright.
IMPLEMENTATION HOOK: Tag every ledger-derived preference/rule with an `expression_type: explicit_stated|inferred_pattern|inferred_single_instance` field and report shadow-mode accuracy broken out by this tag — RealPref's finding predicts your accuracy will be much lower on `inferred_single_instance` rules, so this stratified metric (computable in stdlib with a groupby-style dict aggregation) will surface exactly where the clone is unreliable before a bad prediction reaches production.

**4.2 PersonaGym / PersonaScore (Samuel et al., EMNLP 2025 Findings, arXiv 2407.18416)**
URL: https://arxiv.org/abs/2407.18416 ; https://github.com/vsamuel2003/PersonaGym
First dynamic evaluation framework for persona agents: 200 personas x 10,000 questions, scored across five dimensions — Action Justification, Expected Action, Linguistic Habits, Persona Consistency, and Toxicity Control — each on a calibrated 1-5 rubric via an LLM-judge ensemble (PersonaScore) validated against human ratings. "Expected Action" (does the agent do what this specific person would do in a new scenario) and "Persona Consistency" (does it contradict itself across turns) map almost one-to-one onto what a cognitive-clone eval needs: not just "is this plausible for a person" but "is this plausible for THIS person, consistently."
IMPLEMENTATION HOOK: Borrow the five-axis rubric structure for a lightweight, stdlib-computable eval harness — store each shadow-mode prediction plus its later ground-truth outcome, and periodically batch a sample through an LLM-judge call scoring 1-5 on "matches this person's established pattern" and "internally consistent with prior predictions for this person," writing results to an `eval_scores.json` ledger for trend tracking over time (no bespoke ML infra needed, just prompt + JSON).

**4.3 LaMP (Salemi, Mysore, Bendersky & Zamani, ACL 2024, arXiv 2304.11406)**
URL: https://arxiv.org/abs/2304.11406 ; https://github.com/LaMP-Benchmark/LaMP
Benchmark for personalized language generation/classification with 7 tasks (3 classification, 4 generation), where models are given a per-user profile of past items and must produce personalized outputs; it proposes retrieval-augmented personalization (retrieving relevant past items per profile, comparing term-matching/semantic/time-aware retrievers) as the mechanism, and crucially defines two eval splits — a user-based split (generalize to new, unseen users) and a time-based split (generalize to future interactions of the SAME existing user). The time-based split is exactly the personal-clone setting: same person, later point in time, held-out future decision.
IMPLEMENTATION HOOK: Adopt LaMP's time-based split as the canonical evaluation protocol — always train/derive the self-model only from ledger records before timestamp T and score only on records after T (never shuffle across time), and implement simple retrieval-augmented prediction (return the k most similar past decisions by token-overlap or metadata-match, stdlib only, no embeddings required) as the baseline predictor before reaching for anything fancier.

**4.4 Calibration metrics: Brier score, Expected Calibration Error (ECE), and blind-discriminator (Turing-style) tests**
URL (general reference, no single canonical paper — foundational: Brier 1950; ECE formalized in Guo et al. 2017 "On Calibration of Modern Neural Networks," https://arxiv.org/abs/1706.04599; recent LLM-calibration surveys e.g. https://arxiv.org/abs/2607.08046)
Brier score = mean squared error between predicted probability and the binary outcome (0/1), decomposable into calibration + resolution + uncertainty terms — rewards confident-correct predictions and quadratically penalizes confident-wrong ones, so it directly captures the "predicts what the person would do, with probabilities" requirement. ECE bins predictions by stated confidence and measures the average |confidence − empirical accuracy| gap; contemporary LLM systems show real ECE in the 0.12–0.40 range, i.e., material overconfidence, which is a strong prior that a first-cut personal clone will also be overconfident and needs explicit calibration correction. A "blind discriminator test" (a human or judge model shown a real decision and a clone-predicted one, asked to identify which is real) is the qualitative complement — used informally across persona/twin literature (e.g., PersonaGym's Persona Consistency axis, Park et al. 2024's replication-accuracy framing) as a check that predictions aren't just statistically plausible but indistinguishable from the real person's actual choices.
IMPLEMENTATION HOOK: Compute Brier score and ECE directly in stdlib (no numpy needed — pure Python sums/loops over the JSON ledger of {predicted_probability, actual_outcome} pairs, with confidence bucketed into e.g. 10 bins for ECE) as the two core shadow-mode scalars written to a `metrics.json` file after every batch; separately, run periodic blind discriminator tests by sampling matched pairs (one real decision, one clone-predicted decision for a similar context) and asking a fresh LLM call (no memory of which is which) to guess which is real — track the discriminator's accuracy over time as a qualitative check (accuracy near 50% = clone is convincing; near 100% = clone is easily distinguishable from the real person).

**4.5 Sycophancy vs. true preference (Sharma et al., 2023, arXiv 2310.13548 — "Towards Understanding Sycophancy in Language Models")**
URL: https://arxiv.org/abs/2310.13548
Shows five production AI assistants systematically shift stated views to match the user's expressed opinion, and that both human raters and trained preference/reward models prefer convincing sycophantic (agreement-seeking) responses over correct/consistent ones a non-negligible fraction of the time — traced to biases baked into human-preference training data itself (agreement is rated as more helpful even when wrong). Directly relevant risk for a personal clone: if the clone's predictions are ever shown to the person before being scored, or if any human-in-the-loop feedback used to refine it rewards "told me what I wanted to hear," the resulting self-model will learn the person's stated self-image rather than their actual revealed policy — which is precisely why shadow-mode (scoring only against later real choices, never showing predictions to the subject first) is methodologically necessary, not just a nice-to-have.
IMPLEMENTATION HOOK: Structurally enforce shadow mode in the ledger design — predictions get a separate `predictions.json` store that is never merged into or exposed alongside the person's live decision UI, and only a background process compares `predictions.json` entries to later-arriving `decisions.json` entries after the fact; this file-level separation (pure filesystem/stdlib, no access-control system needed) prevents the contamination pathway described in Sharma et al. by construction.

## 5. Drift detection

**5.1 ADWIN — Adaptive Windowing (Bifet & Gavaldà, SIAM SDM 2007)**
URL: https://www.researchgate.net/publication/220907178_Learning_from_Time-Changing_Data_with_Adaptive_Windowing (paper: "Learning from Time-Changing Data with Adaptive Windowing")
Maintains a variable-length sliding window of recent observations that grows automatically while the stream looks stationary (for statistical power) and automatically shrinks by cutting off the oldest sub-window whenever the means of two sub-windows differ by more than a threshold derived from a rigorous statistical bound — giving provable bounds on both false-positive and false-negative drift-detection rates. The memory/time-efficient variant (ADWIN2) uses a compressed exponential-histogram representation of the window rather than storing every raw point. Directly applicable to monitoring the person's accept/reject rate, or the clone's rolling accuracy, over time without any hand-tuned fixed window size.
IMPLEMENTATION HOOK: Pure-Python ADWIN is straightforward to implement with stdlib only (a list of "buckets" storing count+sum+variance per power-of-two-sized sub-window, per the exponential histogram compression) — feed it the rolling stream of `1 if prediction_correct else 0` (or the person's own decision valence) and it flags a policy-drift changepoint whenever a statistically significant shift in that stream's mean occurs; this is likely the best primary drift detector for the system since it requires no distributional assumptions.

**5.2 Page-Hinkley test and DDM (Drift Detection Method)**
URL (Page-Hinkley, CUSUM-family origin): Page (1954) "Continuous Inspection Schemes," Biometrika — general reference, no single arXiv URL; commonly cited via survey https://www.sciencedirect.com/science/article/pii/S1319157821003062 ("Concept Drift Detection in Data Stream Mining: A literature review"). DDM: Gama, Medas, Castillo & Rodrigues (2004), "Learning with Drift Detection," SBIA — https://www.researchgate.net/publication/2523358 (widely cited via the same survey).
Page-Hinkley is a sequential CUSUM-style test: it accumulates the running deviation of each new observation from the mean-so-far and signals drift once this cumulative sum exceeds a threshold — tuned to catch sustained, gradual shifts rather than single outliers, which suits detecting a slow evolution in someone's policy (e.g., gradually becoming more risk-averse) rather than one-off anomalies. DDM instead monitors the *model's own error rate* directly (assuming error should trend down/flat as more data arrives under a stable concept), tracking error rate p and its standard deviation s, and raises a "warning" then a "drift" alarm at two statistically-defined thresholds on p+s — cheap, well-understood, and specifically framed around a deployed predictor's error stream, matching the personal clone's shadow-mode accuracy stream almost exactly.
IMPLEMENTATION HOOK: Implement both as ~20-line pure-Python stateful classes (running mean + cumulative deviation for Page-Hinkley; running error rate + std for DDM) that consume the same `1/0` correctness stream from the shadow-mode ledger as ADWIN (5.1); running all three in parallel and requiring agreement (e.g., 2-of-3) before declaring "policy drift" is a stdlib-only ensemble that reduces false alarms without any ML library.

**5.3 Bayesian Online Changepoint Detection (Adams & MacKay, 2007, arXiv 0710.3742)**
URL: https://arxiv.org/abs/0710.3742
Maintains an online posterior distribution over the "run length" — time elapsed since the most recent changepoint — via a simple forward message-passing recursion, rather than a single binary drift/no-drift flag; this gives a full probability distribution over "how long has the current regime been stable" and updates it with each new observation in constant amortized work per step given a suitable conjugate model of the within-regime data. Unlike ADWIN/Page-Hinkley/DDM (frequentist, single detected changepoint), BOCPD is naturally suited to giving a *confidence* about how recently the person's policy shifted, and composes cleanly with a Bayesian self-model (e.g., a Beta-Bernoulli per decision-type) since the run-length posterior and the parameter posterior update together.
IMPLEMENTATION HOOK: For decision types modeled as Beta-Bernoulli (binary accept/reject with an unknown probability), the exact BOCPD recursion is closed-form and implementable in stdlib Python (loop over run-length hypotheses, each carrying its own Beta(a,b) sufficient statistics, updated via the standard conjugate update plus a hazard-rate mixing step) — this gives a principled "P(the person's policy on this decision type changed within the last N decisions)" number for free, useful for a drift dashboard without needing scipy/numpy.

## 6. Uncertainty/abstention

**6.1 Learning to defer / Predict Responsibly (Madras, Pitassi & Zemel, NeurIPS 2018, arXiv 1711.06664)**
URL: https://arxiv.org/abs/1711.06664 ; code: https://github.com/dmadras/predict-responsibly
Generalizes the older "reject option"/rejection-learning framework by having the model explicitly learn WHEN to defer to a downstream human decision-maker as part of the optimization objective (jointly optimizing accuracy and, in their framing, fairness), rather than deferring purely on a fixed confidence threshold. Shows empirically that a jointly-trained defer policy beats a naive confidence-threshold cutoff on both accuracy and bias metrics on real datasets — i.e., "when to abstain" is itself learnable and improves on hand-tuned thresholds. Maps directly onto a cognitive clone's core design question: for which decisions should the system predict-and-log silently, versus flag "defer to the person, no reliable prediction available."
IMPLEMENTATION HOOK: Rather than a single global confidence threshold, maintain a per-decision-type defer rate learned from the ledger itself — track predicted-probability vs. actual-outcome per `decision_type` bucket (stdlib dict of running stats) and set/adjust a per-bucket abstention threshold so that the *realized* error rate on non-abstained predictions in that bucket stays under a target (e.g., iteratively raise the bucket's threshold whenever recent non-abstained accuracy in that bucket falls below target) — a simple closed-loop controller implementable without any learning library.

**6.2 Conformal prediction (foundational: Vovk, Gammerman & Shafer 2005 textbook; accessible modern reference: Angelopoulos & Bates, "A Gentle Introduction to Conformal Prediction," arXiv 2107.07511)**
URL: https://arxiv.org/abs/2107.07511
A distribution-free calibration wrapper placed on top of any existing predictor (no retraining needed): given a held-out calibration set, it computes nonconformity scores for calibration examples, and at prediction time returns a *set* of plausible labels/outcomes sized so that, under only the exchangeability assumption (not any parametric distributional assumption), the true outcome is contained in the set with probability at least 1−α, in finite samples — not just asymptotically. Split (inductive) conformal prediction is the practical variant: hold out a calibration slice, compute one nonconformity score per calibration point, and use its (1−α) empirical quantile as the threshold for future prediction sets.
IMPLEMENTATION HOOK: Split conformal prediction is naturally stdlib-friendly — after each self-model update, hold out the most recent K ledger records as a calibration set, compute a simple nonconformity score (e.g., `1 - predicted_probability_of_actual_outcome`) per record with pure Python, sort and take the empirical (1−α) quantile, and use that quantile at prediction time to decide the width of the "prediction set" (e.g., "one of these top-N candidate actions, with ≥90% coverage guarantee") rather than a single point prediction — this gives a formally justified confidence set without numpy/scipy, and is the most rigorous of the abstention mechanisms surveyed here because its guarantee holds regardless of how well-calibrated the underlying probability model is.

**6.3 Just Ask for Calibration (Tian, Mitchell, Zhou, Sharma, Rafailov, Yao, Finn & Manning, EMNLP 2023, arXiv 2305.14975)**
URL: https://arxiv.org/abs/2305.14975
For RLHF-tuned LMs (ChatGPT-class models), *verbalized* confidence — asking the model to state a confidence percentage in natural language as part of its output — is better calibrated than the model's own internal token-probability estimate, reducing ECE by roughly 50% relative on TriviaQA/SciQ/TruthfulQA-style benchmarks; this is notable because RLHF training is known to distort a model's raw output-token probabilities (they become overconfident / poorly calibrated post-RLHF), but asking the model to *say* a number sidesteps that distortion, though prompting alone does not eliminate overconfidence entirely. Practically important for a stdlib-only system since it means "confidence" can be obtained by simply prompting the LLM to emit a number, rather than needing access to internal logits/logprobs.
IMPLEMENTATION HOOK: When using an LLM to generate the clone's prediction, explicitly prompt it to also emit a verbalized confidence (e.g., "state your confidence 0-100 that this matches what {person} would actually do") and log the number as a plain field in the JSON ledger record — then empirically recalibrate it post-hoc using the same Brier/ECE machinery from section 4.4 (a simple isotonic-regression-free method: bucket verbalized-confidence into deciles, replace each decile's stated confidence with the observed empirical accuracy for that decile, store this correction as a `calibration_map.json` lookup table applied at prediction time — no ML library required).

## 7. Reflection & distillation

**7.1 Reflexion (Shinn, Cassano, Berman, Gopinath, Narasimhan & Yao, NeurIPS 2023, arXiv 2303.11366)**
URL: https://arxiv.org/abs/2303.11366 ; https://github.com/noahshinn/reflexion
Reinforces a language agent purely through linguistic feedback rather than weight updates: after each trial, the agent verbally reflects on the outcome/feedback signal ("what went wrong / what should change"), stores that reflection as text in an episodic memory buffer, and conditions subsequent attempts on the accumulated reflections — no fine-tuning required. This is the clearest existing template for "evidence reflection improves later prediction" cited in the brief: the mechanism is textual self-critique persisted as memory, cheaply implementable with any LLM call plus a text store.
IMPLEMENTATION HOOK: After each shadow-mode prediction is scored against the real later outcome, if it was wrong (or low-confidence-but-wrong), trigger one LLM call asking "why did the clone's prediction diverge from the actual choice, and what rule should be updated" and append the resulting free-text reflection to a `reflections.jsonl` file keyed by decision_type; feed the most relevant recent reflections (simple keyword/tag match, stdlib only) into the prompt context for future predictions of that decision_type — a direct, low-effort Reflexion port.

**7.2 Reflection mechanism in Generative Agents (Park et al. 2023)** — see also section 3.1.
URL: https://arxiv.org/abs/2304.03442
Complementary to Reflexion: rather than reflecting only after an explicit failure signal, Generative Agents run reflection periodically/proactively — when the sum of importance scores of recent memories crosses a threshold, the agent asks itself 3 salient high-level questions about recent memories, retrieves the memories relevant to each question, and synthesizes a higher-level insight statement ("Klaus Mueller is dedicated to his research on gentrification" from many small observations), which is itself stored back into the memory stream and can be retrieved/built upon recursively (reflections about reflections), forming a tree. Ablations in the paper show removing reflection significantly hurts long-horizon behavioral coherence — synthesis, not just raw retrieval, is what keeps the agent "in character" over time.
IMPLEMENTATION HOOK: Complement the failure-triggered Reflexion-style reflection (7.1) with a scheduled, threshold-triggered reflection pass (e.g., every N new ledger records, or when cumulative "importance" — a simple heuristic like decision stakes/frequency of similar past decisions — crosses a threshold) that asks the LLM 2-3 self-generated questions about the person's recent decisions and synthesizes higher-level self-model statements into a `self_model.json`; store provenance (which raw ledger records fed each synthesized statement) so any statement can later be traced back and revised, all via plain JSON files.

**7.3 A-MEM: Agentic Memory for LLM Agents (2025, arXiv 2502.12110, NeurIPS 2025)**
URL: https://arxiv.org/abs/2502.12110 ; https://github.com/agiresearch/a-mem
Zettelkasten-inspired memory system: each new memory is stored as an atomic "note" with LLM-generated keywords/tags/context, then the system autonomously creates links between the new note and semantically related historical notes and *updates the attributes of the old notes it links to* (bidirectional memory evolution, not append-only), rather than using a fixed, hand-designed memory schema. Reports up to 6x improvement on complex multi-hop reasoning tasks and 85-93% reduction in memory-operation token usage versus prior memory-system baselines — evidence that dynamically-linked, evolving memory beats flat/static retrieval for tasks requiring connecting many small facts (relevant to a self-model needing to connect many small past decisions into coherent policy statements).
IMPLEMENTATION HOOK: Extend the flat JSON ledger with a lightweight "note" layer — each synthesized self-model statement (from 7.2) gets a small record `{id, text, tags, linked_ids}`; when adding a new statement, do a cheap stdlib similarity pass (tag overlap / token-Jaccard against existing statements, no embeddings needed) to find and link related prior statements, and allow the linking step to also append a short "updated in light of new evidence" note to the older linked statement — a stdlib-only approximation of A-MEM's bidirectional-update idea, avoiding a vector database.

**7.4 Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory (2025, arXiv 2504.19413)**
URL: https://arxiv.org/abs/2504.19413 ; https://github.com/mem0ai/mem0
Production memory-layer architecture that extracts, consolidates, and retrieves salient facts from conversation history rather than replaying full transcripts; reports 91% lower p95 latency and >90% token-cost savings versus full-history prompting, plus a 26% relative improvement on an LLM-as-judge quality metric, and states explicitly that in their production experience "agents do not fail on model quality first — they fail on memory" (i.e., context-management failures dominate over raw model capability failures). Directly supports the design decision to build a real ledger + consolidation/retrieval layer (as this brief specifies) rather than stuffing an ever-growing raw history into every prompt.
IMPLEMENTATION HOOK: Never pass the full raw ledger into an LLM prediction call — implement a cheap consolidation step (stdlib): periodically summarize groups of raw ledger records sharing a `decision_type` into a single consolidated fact/rule entry once the group exceeds a size threshold, retire the raw records to a cold-storage JSON file (kept for audit/replay but not loaded into the hot prediction context), and always retrieve only the top-k consolidated facts + a few most-recent raw records for any given prediction — mirrors Mem0's extract-consolidate-retrieve pipeline with zero external dependencies.

## 8. Augmentation/decision support

**8.1 Superforecasting / Good Judgment Project (Tetlock & Gardner, book 2015; underlying IARPA ACE tournament research by Tetlock, Mellers & Moore)**
URL: https://goodjudgment.com/resources/the-superforecasters-track-record/ ; background: https://en.wikipedia.org/wiki/The_Good_Judgment_Project
Over a 4-year, ~500-question, 1M+-forecast IARPA tournament, the Good Judgment Project's top forecasters ("superforecasters") beat the aggregate of intelligence-community analysts with access to classified data by roughly 30%, and superforecasters' 400-day-ahead forecasts were about as accurate as ordinary forecasters' 150-day-ahead forecasts (i.e., a ~250-day accuracy lead). Roughly 70% of identified superforecasters retained top-tier status year over year, meaning calibrated forecasting skill is a persistent, measurable trait, not one-off luck. The methodological ingredients — probabilistic (not binary) forecasts, frequent belief updating, active tracking of one's own track record via Brier scoring, and combining diverse evidence sources — are a template for what a well-calibrated clone's internal forecasting discipline should look like, and the persistence finding argues that a person's own decision policy, once well-characterized, should also be a fairly stable target to track (making drift detection meaningful rather than chasing noise).
IMPLEMENTATION HOOK: Borrow the "keep a running personal Brier score visible to the forecaster" discipline directly — surface the clone's own rolling Brier score/ECE (already logged per section 4.4) back into whatever review UI the lab builds, since GJP found that this kind of continuous self-scoring feedback loop is part of what produces persistent forecasting skill, not just the probabilistic-thinking style itself.

**8.2 Noise: A Flaw in Human Judgment (Kahneman, Sibony & Sunstein, 2021)**
URL: https://en.wikipedia.org/wiki/Noise:_A_Flaw_in_Human_Judgment (book; no single arXiv source — cite as Kahneman, D., Sibony, O., & Sunstein, C. R. (2021). Noise: A Flaw in Human Judgment. Little, Brown Spark.)
Distinguishes "bias" (systematic, directional error) from "noise" (unwanted, unexplained variability — the same person or different people giving different judgments on effectively identical cases), and introduces the "noise audit" methodology: have multiple judges (or the same judge at different times) independently evaluate identical cases and measure the spread. Demonstrated across medicine, law, forecasting, and hiring that noise is often as large a contributor to error as bias, and crucially is usually invisible to the people producing it (nobody notices their own inconsistency without an audit). Directly relevant to the personal-clone project: a "policy drift" detector needs to distinguish genuine drift (systematic change in the person's policy — a bias-like directional shift) from mere noise (the person being inconsistent on functionally identical decisions without their policy actually changing) — conflating the two would cause false drift alarms.
IMPLEMENTATION HOOK: Before flagging drift (section 5), run a lightweight internal noise check: identify near-duplicate historical decision contexts (same decision_type + similar key fields) and measure the variance of the person's own outcomes on those duplicates; if that within-person noise floor is high, widen the drift-detector's threshold accordingly (e.g., scale the ADWIN/Page-Hinkley threshold by the estimated noise standard deviation) so genuine policy drift isn't confused with the person simply being inconsistent — a stdlib variance calculation over grouped ledger records.

**8.3 Algorithm aversion (Dietvorst, Simmons & Massey, Journal of Experimental Psychology: General, 2015)**
URL: https://pubmed.ncbi.nlm.nih.gov/25401381/ ; https://marketing.wharton.upenn.edu/wp-content/uploads/2016/10/Dietvorst-Simmons-Massey-2014.pdf
Across 5 studies, people who watched an algorithm make a forecasting error (even a small one, even when the algorithm still outperformed a human forecaster overall) lost confidence in it and switched to a demonstrably worse human forecaster far more readily than people who watched a human make the identical error — i.e., algorithmic errors are judged more harshly than equivalent human errors, and a single visible mistake can permanently sour trust. Follow-up work (Dietvorst et al. 2016, Management Science, "Overcoming Algorithm Aversion") found that letting users make even small, cosmetic modifications to an imperfect algorithm's output substantially restored their willingness to use it. Directly informs how any prediction/recommendation surface built on top of the clone should be designed: never present a bare, unexplained wrong prediction, and give the person a lightweight way to adjust/override outputs even if the adjustment is cosmetic.
IMPLEMENTATION HOOK: If/when the clone's predictions are ever surfaced to the person (post-shadow-mode, i.e., once it graduates from pure evaluation), log every override/edit the person makes to a suggested action as a first-class ledger event (`event_type: edit`, already specified in section 1) — both because it is high-signal training data (per 1.4) and because Dietvorst's follow-up shows the mere ability to edit is itself what sustains trust, so the UI/UX should always allow light-touch edits rather than binary accept/reject only.

**8.4 Human-AI complementarity and mental-model updating (Bansal, Wu, Zhou, Fok, Nushi, Kamar, Ribeiro & Weld, CHI 2021)**
URL: https://dl.acm.org/doi/10.1145/3411764.3445717
Studies when human+AI teams outperform either alone ("complementary performance"). Central, counterintuitive finding: adding AI-generated explanations did not increase complementary team performance — instead, explanations mainly increased the rate at which humans accepted the AI's recommendation *regardless of whether it was correct*, i.e., explanations mostly drove over-reliance/acceptance rather than better-calibrated trust; a broader survey the group cites (100+ empirical studies) confirms explainability alone is not a reliable predictor of improved human-AI team outcomes. This is a direct caution against naively surfacing the clone's reasoning/justification as a trust-building feature — plausible-sounding rationale can increase acceptance of wrong predictions just as much as right ones.
IMPLEMENTATION HOOK: If the clone's predictions are eventually surfaced with rationale, always pair the rationale with the clone's actual calibrated confidence/accuracy for that decision_type (from sections 4.4/6.3) rather than rationale alone — Bansal et al.'s finding implies rationale without a visible, honest accuracy signal will just increase blind acceptance; the calibration_map and per-bucket accuracy stats already logged (sections 4, 6) are exactly the numbers that should always accompany any surfaced explanation.

## 9. Security & consent

**9.1 UCAN — User Controlled Authorization Networks (ucan-wg spec, ongoing; originated at Fission)**
URL: https://ucan.xyz/specification/ ; https://ucan.xyz/revocation/ ; https://fission.codes/blog/a-guide-to-ucans/
A decentralized capability-token format extending JWTs: a UCAN directly embeds the capabilities it grants (rather than pointing to a central ACL), supports delegation chains where each delegation must "attenuate" (only narrow, never widen) the capability it derives from, works offline/local-first since verification needs no round-trip to an issuing server, and has an explicit revocation spec — a delegator can publish an unforgeable revocation message that invalidates a specific delegation path, at the cost of eventual (not instant) consistency under network partition. This is a strong architectural fit for "capability tokens for consent and delegation" in a system where a person is granting an AI clone specific, narrow, revocable authority (e.g., "you may predict my email triage decisions but not draft financial approvals").
IMPLEMENTATION HOOK: Even without adopting the full UCAN cryptographic stack, borrow its core data model in stdlib JSON: a `grants.json` ledger of `{capability, scope, issued_by, issued_to, expires_at, parent_grant_id}` records where every grant must be a strict subset of its parent's scope (checkable with plain Python), plus a `revocations.json` append-only list of revoked grant ids that every capability check consults — gives auditable, delegable, revocable consent scoping for what the clone is allowed to predict/act on, with zero external dependencies.

**9.2 Macaroons: Cookies with Contextual Caveats for Decentralized Authorization (Birgisson, Politz, Erlingsson, Taly, Vrable & Lentczner, Google Research, NDSS 2014)**
URL: https://research.google/pubs/macaroons-cookies-with-contextual-caveats-for-decentralized-authorization-in-the-cloud/ ; https://theory.stanford.edu/~ataly/Papers/macaroons.pdf
Bearer credentials built from chained HMACs, as cheap to issue/verify as a web cookie, that carry "caveats" — arbitrary predicates (e.g., "only valid before time T," "only for operation X," "only if parent condition Y also holds") appended by anyone holding the macaroon, each caveat only ever *narrowing* what the credential authorizes, never widening it, and third-party caveats can even require a separate discharge macaroon from another service (contextual, cross-domain confinement). The chained-HMAC construction makes verification pure symmetric-key crypto (fast, no PKI needed) while still supporting decentralized delegation.
IMPLEMENTATION HOOK: For a stdlib-only Python system, macaroons are directly implementable with `hmac`+`hashlib` from the standard library (no external crypto library required): mint a root token with `hmac.new(secret, msg, sha256)`, and each delegation step appends a caveat string and re-derives the HMAC chained over the previous signature — giving self-contained, offline-verifiable, narrowing-only capability tokens for consent scoping (e.g., "clone may read calendar decisions from ledger, expires in 30 days, cannot be used for financial decisions") without needing a database of active sessions.

**9.3 EU AI Act, Article 50 — transparency obligations for AI-generated/manipulated content (applies from 2 August 2026, marking/detection obligation extended to 2 December 2026 for pre-existing systems)**
URL: https://digital-strategy.ec.europa.eu/en/faqs/transparency-obligations-under-article-50-ai-act ; https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-50
Requires deployers to disclose "deepfake"-class AI-generated/manipulated content that resembles a real person to any natural person exposed to it, at the latest upon first exposure, via a clear and perceivable label (visible or audible) — and this obligation applies even absent any intent to deceive (resemblance alone triggers it). A narrow carve-out exists for evidently artistic/satirical/fictional works (reduced to a lighter disclosure standard). Non-compliance penalties reach up to €15M or 3% of global annual turnover. Given the target date (2 August 2026) is imminent relative to "today," this is a live, near-term compliance constraint, not a hypothetical one, for any system that could produce outputs resembling the real person it clones.
IMPLEMENTATION HOOK: Any output surface where the clone's predicted decision, message draft, or synthesized "what {person} would likely say" content could be mistaken for the real person's own words/voice must carry a persistent, unambiguous machine-and-human-readable label — store a `synthetic: true` / `generated_by: cognitive_clone_v{n}` field on every clone-produced artifact in the JSON ledger and propagate that flag into any rendering layer, so the disclosure requirement is enforced structurally (the artifact literally cannot be displayed without the flag being checked) rather than relying on UI convention alone. UNVERIFIED: whether a *shadow-mode-only, never-surfaced* prediction (this system's stated default mode) falls inside Article 50's scope at all is a genuine open legal question — the disclosure duty is triggered by exposing a natural person to the content, and shadow-mode predictions are, by the lab's own design, never shown to anyone as if from the real person — but confirm with counsel before assuming this exempts the system, especially once/if predictions are surfaced to third parties (e.g., team members approving on the person's behalf).

**9.4 Tennessee ELVIS Act (Ensuring Likeness Voice and Image Security Act, signed 21 March 2024, effective 1 July 2024)**
URL: https://en.wikipedia.org/wiki/ELVIS_Act ; https://www.hklaw.com/en/insights/publications/2024/07/firstofitskind-artificial-intelligence-law-addresses-deep
First-in-the-nation state law explicitly adding "voice" (defined to include both the actual voice and a simulation of it) as a protected property right alongside name/image/likeness; unauthorized commercial use is both a civil cause of action and a Class A misdemeanor (up to 11 months 29 days jail / $2,500 fine). Establishes that a sufficiently accurate voice/likeness simulation of a specific, identifiable real person is legally treated as *that person's protected property*, independent of whether it's labeled as synthetic — a stricter standard than the EU's "must disclose" approach, since Tennessee additionally restricts unauthorized commercial *use* itself, not just requiring disclosure.
IMPLEMENTATION HOOK: If any component of the system produces audio/voice or highly personalized likeness output (not just text predictions) modeling the specific person, treat state-level right-of-publicity/voice-property statutes like ELVIS as a hard requirement for the person's own explicit, revocable consent grant (tie into the UCAN/macaroon consent-token design in 9.1/9.2 — a specific `capability: voice_synthesis` scope, separately grantable/revocable from `capability: text_prediction`), and store consent proof (timestamp, scope, method) in the ledger as an auditable record independent of the prediction ledger.

**9.5 NO FAKES Act (federal, US) — status as of this research pass**
URL: https://www.congress.gov/bill/119th-congress/senate-bill/1367 ; https://www.congress.gov/bill/119th-congress/house-bill/2794 ; revised version tracker: https://www.blackburn.senate.gov/2026/5/technology/blackburn-coons-salazar-dean-colleagues-introduce-revised-version-of-no-fakes-act
Proposed federal IP right protecting individuals against unauthorized "digital replicas" of voice and visual likeness; S.1367/H.R.2794 (119th Congress, reintroduced April 2025) remain pending in the Senate and House Judiciary Committees respectively — NOT yet enacted as of this research pass, though a revised version was introduced by Blackburn/Coons/Salazar/Dean and colleagues (per a May 2026 press release), indicating active, ongoing legislative work rather than a stalled bill. Provisions include an authorization right for the individual, notice-and-takedown process, and First-Amendment-protected-speech carve-outs (news, sports broadcast, satire). STATUS: UNVERIFIED whether the bill has passed either chamber as of the current date — treat as pending federal legislation, not current law, and re-check congress.gov before any compliance claim.
IMPLEMENTATION HOOK: Because NO FAKES (if enacted) and ELVIS-style state laws both converge on "affirmative, revocable, individual consent for likeness/voice replication," design the consent-token layer (9.1/9.2) to be jurisdiction-agnostic now — a scoped, revocable, auditable per-capability grant model satisfies the strictest plausible version of either regime, so building it before the law finalizes avoids a costly retrofit.

## 10. Limits

**10.1 Prediction contamination / shadow-mode rationale (Hawthorne effect / reactivity + Sharma et al. sycophancy, cross-referenced)**
URL (Hawthorne/reactivity, general reference): https://en.wikipedia.org/wiki/Hawthorne_effect ; https://en.wikipedia.org/wiki/Reactivity_(psychology) ; sycophancy: https://arxiv.org/abs/2310.13548 (see 4.5)
The Hawthorne effect and the broader "reactivity" literature establish that people systematically change behavior when they know they are being observed/measured — the original Hawthorne Works studies famously found productivity rose under *both* increased and decreased lighting, because workers were reacting to being watched, not to the manipulated variable itself. Applied directly to a cognitive clone: if the person ever sees the clone's prediction of their own choice before making it, their subsequent choice is no longer an independent ground-truth label — it's contaminated by the prediction itself (they may conform to it, react against it out of spite/autonomy-assertion, or overthink it), which invalidates using that later choice to score the earlier prediction. Combined with the sycophancy finding (4.5) that models trained on human feedback learn to tell people what they want to hear, this is the core methodological argument for shadow mode: predictions must be scored only against choices the person made with no knowledge that a prediction existed, or the entire evaluation loop measures self-fulfilling-prophecy conformity/reactance rather than genuine predictive accuracy.
IMPLEMENTATION HOOK: Enforce a structural, not policy-level, separation (already specified in 4.5) — `predictions.json` is write-only from the prediction process and never read by anything the person interacts with; a separate read-only auditor process compares it against `decisions.json` after the fact. Additionally, log an `exposure_check` boolean per decision (best-effort: did any UI the person used in this session render a clone-derived suggestion for this decision_type recently) so any accidentally-contaminated evaluation records can be filtered out of the accuracy metrics rather than silently inflating (or deflating, if reactance dominates) the score.

**10.2 Goodhart's Law (Goodhart 1975; popularized as "when a measure becomes a target, it ceases to be a good measure" — Strathern 1997)**
URL: https://en.wikipedia.org/wiki/Goodhart%27s_law ; Strathern, M. (1997). "'Improving ratings': audit in the British university system." European Review, 5(3), 305-321.
Any statistical regularity used as a control/optimization target tends to break down once it is targeted, because agents (here, potentially both the person and the system's own tuning process) adapt behavior to game the metric rather than the underlying quality it was meant to proxy. For a personal clone, the two most likely Goodhart failure modes are: (a) if the clone's accuracy score itself becomes a target that developers optimize against, the system may learn to predict the *easy, low-entropy majority-class* decisions well (inflating aggregate accuracy) while remaining useless on the hard, high-stakes, judgment-call decisions that actually matter; and (b) if the person becomes aware their decisions are being scored against a model's predictions (even in nominal shadow mode), they may unconsciously start making decisions that are more predictable/consistent than they otherwise would be, again inflating the score without the model having gotten better.
IMPLEMENTATION HOOK: Never report a single aggregate accuracy number as the system's headline metric — always report stratified metrics (already implied by 4.1's expression_type breakdown and 4.4's per-bucket Brier/ECE) by decision_type x stakes-level x expression_type, and specifically track accuracy on a held-out set of the *hardest* historical decisions (highest historical disagreement/edit rate, per the routine-mining buckets in 2.3) as a separate, harder-to-game headline number precisely because it's the metric most resistant to Goodharting via majority-class exploitation.

**10.3 Self-consistency ceilings (test-retest reliability of human self-report / behavior)**
URL: general reference — self-report test-retest reliability literature, e.g. https://www.pnas.org/doi/10.1073/pnas.1818430116 ("Large-scale analysis of test-retest reliabilities of self-regulation measures," PNAS); directly quantified for the clone-evaluation setting in Park et al. 2024 (3.2) and Twin-2K-500 (3.4)
Even asking the same person the same question twice, weeks apart, does not yield identical answers — self-report measures show meaningfully-less-than-perfect test-retest reliability, and behavioral-task measures are considerably *less* reliable than self-report measures (i.e., what someone actually does is noisier across repetitions than what they say about themselves). This sets a hard ceiling on achievable clone accuracy: a clone cannot be more consistent with a real decision than the real person is with their own past/future self, and Park et al. 2024's headline 85% figure (3.2) is explicitly framed as 85% *of that ceiling*, not 85% of a theoretical 100%. Treating 100% accuracy as the goal, rather than "matches the person's own self-consistency," sets an unachievable and misleading target.
IMPLEMENTATION HOOK: As specified in 3.2/3.4, always compute and report clone accuracy normalized against an empirically estimated `human_self_consistency_estimate` per decision_type (derived from repeat/near-duplicate decisions in the ledger, per Twin-2K-500's repeat-wave design) rather than against a raw 100% ceiling; this single normalization changes the entire interpretation of "success" for the project and should be treated as a first-class metric definition decision, not an optional refinement.

## Summary — 12 most decision-relevant findings for building this system

1. Capture the atomic decision as a structured (context, options, choice, event_type, latency, rationale) JSON record — Mind2Web's (Target Element, Operation) schema and Centaur's "trial in natural language" both point to this same shape, and it is the substrate every later mechanism (routines, reflection, drift, calibration) reads from.
2. Treat edits/corrections to a proposed action as higher-signal than plain accept/reject — this is both a DAgger-style correction signal (2.1) and Dietvorst's finding (8.3) that letting people lightly edit outputs is what sustains their trust, so it's valuable for both training data and product design.
3. There is a hard, non-zero ceiling on achievable accuracy set by the person's own self-consistency (85% of ceiling in Park et al. 2024, 3.2); always normalize and report against an estimated per-person, per-decision-type consistency floor, never against 100%.
4. Shadow mode is not a nice-to-have but methodologically load-bearing: Hawthorne/reactivity effects (10.1) plus sycophancy (4.5) mean any prediction shown to the subject before their real decision contaminates the very label used to score it — enforce this with a structural (filesystem/process) separation, not a policy.
5. Use LaMP's time-based split (4.3) as the canonical evaluation protocol: train only on records before T, score only on records after T for the same person — never a random shuffle split.
6. Score with Brier score and ECE (4.4), not raw accuracy alone, since the system explicitly needs calibrated probabilities, not just point predictions; both are implementable in pure Python with no numerical libraries.
7. Run at least two independent drift detectors in parallel (ADWIN + Page-Hinkley/DDM, section 5) requiring agreement before declaring policy drift, and explicitly separate genuine drift from mere "noise" (Kahneman et al., 8.2) by first estimating the person's own inconsistency rate on near-duplicate decisions.
8. Build a defer/abstain mechanism with a per-decision-type, empirically-adjusted threshold (learning-to-defer, 6.1) rather than one global confidence cutoff, and consider split conformal prediction (6.2) for a formally-guaranteed confidence-set alternative to point predictions.
9. Reflection (Reflexion 7.1, Generative Agents 7.2) — both failure-triggered and periodically-scheduled synthesis passes over the raw ledger into higher-level self-model statements — measurably improves later prediction quality and is cheap to implement as scheduled LLM calls over JSON files.
10. Never surface rationale/explanation without also surfacing calibrated accuracy for that decision type: Bansal et al. (8.4) found explanations mainly increase blind acceptance, not accuracy, so pairing every explanation with an honest confidence/accuracy number is a safety requirement, not a UX nicety.
11. Build consent/authorization as scoped, delegable, revocable capability tokens (UCAN/macaroons, 9.1/9.2) from day one — implementable with stdlib hmac/json — because EU AI Act Art. 50 (live from Aug 2026), Tennessee's ELVIS Act (live now), and the pending federal NO FAKES Act all converge on the same requirement (affirmative, revocable, auditable per-capability consent), so building it early avoids a retrofit regardless of which regime ultimately binds.
12. Guard against Goodhart's Law (10.2) by never reporting a single aggregate accuracy number — always stratify by decision_type, stakes, and expression-explicitness (RealPref, 4.1), and specifically track accuracy on the hardest/most-edited historical decisions as the headline number, since that subset is the one most resistant to being gamed by majority-class exploitation.
